A Practical Evaluation Model for RAG Systems

Separate retrieval quality from generation quality so teams can diagnose the real source of RAG failures.

Start by separating two systems

A Retrieval-Augmented Generation application contains at least two quality problems: finding useful context and generating an answer from that context. If those dimensions are collapsed into one score, diagnosis becomes difficult.

Retrieval quality

Measure whether relevant documents are returned, whether irrelevant context dominates the result set and whether ranking places the most useful evidence early enough for the model to use it. Precision, recall and context relevance are useful starting points.

Generation quality

Once context is available, evaluate whether the answer is faithful to that context, addresses the question, avoids unsupported claims and clearly communicates uncertainty where evidence is insufficient.

Compare components experimentally

Embedding models, chunking, hybrid retrieval and rerankers should be compared on controlled query sets. Keeping the same evaluation dataset makes architecture decisions evidence-driven rather than preference-driven.

Use failure categories

Classify failures as retrieval misses, ranking problems, context overload, generation errors or unsupported answers. Those categories point to different engineering fixes and make evaluation operationally useful.
